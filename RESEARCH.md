## Prometheus defects addressed

The upstream client calls `connect(5)` but does not start the WebSocket worker. The cache inserts a hero once instead of replacing it after selection. Incoming player IDs are trusted; malformed BSON can throw outside the dispatch handler; unknown message deserialization lacks a return. Shared identity/connected state is unsynchronized. Remote leave/disconnect paths retain dead entity entries. Remote spawn assigns the gameplay entity resource to the controller's hero ID. The leave log has a missing format argument.

This branch adds a shared validated relay and schema, starts the receive worker, locks identity/hero state, publishes atomic connection state, bounds the receive queue, caches selections before connecting, makes reconnect explicit, guards resource/component lookups, erases departed entities and clears disconnected entity maps. DLL compilation passed. These runtime fixes have not been demonstrated in-game.

The patcher uses fixed file offsets including `0x113C110` and `0x137E000`; the DLL calls game functions at fixed addresses. The upstream description of a version-independent patch does not establish retail compatibility. No verified executable fingerprints or alternate offset tables were found in the inspected baseline.

Issues [#41](https://github.com/saturn-xvi/prometheus/issues/41) (access violation), [#8](https://github.com/saturn-xvi/prometheus/issues/8) (build/setup) and version-support discussions identify useful reproduction targets but are not local crash evidence. PRs [#22](https://github.com/saturn-xvi/prometheus/pull/22), [#27](https://github.com/saturn-xvi/prometheus/pull/27) and [#39](https://github.com/saturn-xvi/prometheus/pull/39) were inspected for build, networking and hero-health ideas. GitHub PR status alone does not prove a change exists in the pinned checkout. Historical stat guesses and unverified weapon fixes were not adopted.

## Original game systems and remaining unknowns

The source's entity admins distinguish Lobby, Game and Replay. Game entities use components and STU resources, while Statescript dispatches game messages. The game's JAM/mirror paths and lobby/menu services are not reproduced by the custom BSON relay. `serialization.cpp` explicitly excludes lists, pointers and a rotation matrix from `MovementState`; it cannot synchronize combat, animation state, objectives or complete world state.

OWLib's distinct structured-data parsers are evidence against blindly reusing beta layouts for retail. Final retail resource schemas, entity/component addresses, connection/auth state transitions and original match packet formats remain unverified without a target client. Server-side authoritative game rules are not provided by any evaluated repository.

The fastest evidence-based route is a source-built beta baseline, then one map/hero and two real clients, alongside fingerprinted retail analysis when files become available. A 12-socket synthetic test verifies relay capacity; it does not demonstrate 6v6 gameplay. See [FEATURE_MATRIX.md](FEATURE_MATRIX.md) for precise status.
